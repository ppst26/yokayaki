# Specification: Loyalty Program Design (loyalty-program.md)

เอกสารดีไซน์ระบบสมาชิกสะสมแต้ม (Loyalty Program) สำหรับร้าน Yokayaki Izakaya รายละเอียดการสะสมแต้ม แลกส่วนลดแทนเงินสด และตัวอย่างการลงบัญชี

---

## 1. การสมัครและการค้นหาสมาชิก (Member Registration & Search)

เพื่อความสะดวกรวดเร็วในบรรยากาศร้านที่เร่งรีบ ระบบจะใช้ **"หมายเลขโทรศัพท์มือถือ"** เป็นกุญแจหลักในการระบุตัวตนลูกค้า:

*   **การค้นหาสมาชิก:** ในหน้าชำระเงินของ POS จะมีช่องค้นหาสมาชิก พนักงานกรอกเบอร์โทรศัพท์ 10 หลักของลูกค้าเพื่อดึงข้อมูลชื่อและจำนวนคะแนนคงเหลือ
*   **การสมัครสมาชิกด่วน (Quick Register):** หากค้นหาไม่พบเบอร์ในระบบ พนักงานสามารถกดปุ่ม "สมัครสมาชิกด่วน" แล้วพิมพ์เพียง **[ชื่อลูกค้า]** และ **[เบอร์โทรศัพท์]** กดยืนยันปุ๊บก็สามารถสะสมแต้มของบิลนั้นได้ทันที

---

## 2. ลอจิกการสะสมและการแลกแต้ม (Points Calculation & Redemption Logic)

ระบบใช้ลอจิกอัตราส่วนคงที่ เพื่อให้เจ้าของร้านคำนวณต้นทุนการตลาดและตรวจสอบหนี้สินคะแนนค้างจ่ายได้อย่างแม่นยำ

### 2.1 อัตราการสะสมแต้ม (Earning Rule)
*   **อัตราส่วน:** **ทุกยอดใช้จ่าย 25 บาท ➡️ ได้รับ 1 แต้ม** (ปัดเศษทศนิยมทิ้ง)
*   **เงื่อนไขการได้แต้ม:** ระบบจะคำนวณแต้มสะสมจาก **"ยอดชำระเงินจริงหลังหักส่วนลดสมาชิกแล้วเท่านั้น"** (Net Paid) เพื่อไม่ให้เกิดการคำนวณซ้อน (Double-Dipping) เช่น หากใช้แต้มลดราคาไปแล้ว ยอดส่วนลดนั้นจะไม่นำมาคำนวณแต้มสะสมเพิ่มให้อีกรอบ

### 2.2 อัตราการแลกแต้ม (Redemption Rule)
*   **มูลค่าแต้ม:** **1 แต้ม = ส่วนลดแทนเงินสด 1 บาท** (Fixed Rate)
*   **การใช้งาน:** ลูกค้าสามารถเลือกใช้แต้มสะสมเท่าใดก็ได้ที่มีอยู่ (ไม่บังคับว่าต้องเป็นขั้นต่ำเป็นบล็อก) โดยแต้มจะถูกหักออกไป และแปลงเป็นส่วนลดหักยอดบิลรวมทันที

## 3. ตัวอย่างสถานการณ์จำลองการคำนวณ (Concrete Scenario Example)

### 3.1 ข้อมูลสมมติ
*   **ลูกค้า:** คุณใบเตย (เบอร์โทร `081-234-5678`) ปัจจุบันมีคะแนนสะสมค้างอยู่ **`50 แต้ม`** (มีมูลค่าส่วนลด 50 บาท)
*   **บิลโต๊ะ 2 วันนี้:** มียอดรวมค่าอาหารและเครื่องดื่มทั้งหมด = **`820 บาท`**

### 3.2 ขั้นตอนชำระเงินที่เครื่อง POS
1.  คุณใบเตยแจ้งพนักงานว่าต้องการเช็คบิลและขอสะสมแต้มพร้อมกรอกเบอร์โทรศัพท์
2.  พนักงานกรอกเบอร์ `0812345678` บนหน้าจอ POS ระบบแสดงข้อมูลสมาชิกชื่อ **"คุณใบเตย"** และคะแนนคงเหลือ **"50 แต้ม"**
3.  คุณใบเตยแจ้งว่า **"ขอใช้แต้มลดราคา 50 บาทที่เหลือทั้งหมดเลย"**
4.  พนักงานกดปุ่ม "ใช้คะแนนสะสมลดราคา" ➡️ กรอกจำนวนแต้มที่ต้องการแลก = `50` แต้ม
5.  **ระบบ POS คำนวณยอดเงินใหม่ทันที:**
    *   ยอดรวมบิลปกติ (Gross Amount): `820 บาท`
    *   หักส่วนลดสมาชิก (Points Discount): `-50 บาท` (หักจาก 50 แต้ม)
    *   **ยอดชำระเงินสุทธิ (Net Amount to Pay): 820 - 50 = 770 บาท**
6.  คุณใบเตยโอนจ่ายเงินจำนวน **770 บาท** พนักงานตรวจสอบสลิปและกดยืนยันรับเงินเพื่อปิดบิล

### 3.3 ลอจิกการอัปเดตแต้มหลังชำระเงินสำเร็จ
หลังพนักงานกดปิดบิลชำระเงิน ระบบจะทำงานดังนี้:
1.  **หักแต้มสะสมที่คุณใบเตยแลกใช้ไป:** จากเดิม 50 แต้มลดเหลือ `0 แต้ม`
2.  **คำนวณแต้มสะสมใหม่จากยอดจ่ายจริง:**
    *   ยอดคำนวณแต้ม = ยอดจ่ายจริง `770 บาท` (ไม่ได้คำนวณจากยอด 820 บาทเดิม)
    *   แต้มใหม่ที่ได้รับ = `Floor(770 / 25) = 30.8` ปัดทศนิยมทิ้งเหลือ ➡️ **`30 แต้ม`**
3.  **ยอดคะแนนคงเหลือในระบบของคุณใบเตยสำหรับครั้งต่อไป:** `0 + 30 = 30 แต้ม` (มูลค่า 30 บาท)

## 4. บันทึกข้อมูลธุรกรรมลงฐานข้อมูล (Database Log Entries)
เมื่อปิดบิล ข้อมูลจะบันทึกลงฐานข้อมูล Supabase เพื่อตรวจสอบบัญชี:

```json
// บันทึกในตาราง payments
{
  "order_id": "ORD-009",
  "gross_amount": 820.00,
  "loyalty_discount": 50.00,      // ต้นทุนส่วนลด Loyalty เดือนนี้
  "net_paid": 770.00,             // ยอดเงินโอนจริงที่เข้าบัญชีร้าน
  "payment_method": "TRANSFER"
}

// บันทึกในตาราง loyalty_transactions
{
  "member_id": "MEM-004",
  "order_id": "ORD-009",
  "points_redeemed": 50,          // จำนวนแต้มที่เคลียร์ออก
  "points_earned": 30,            // จำนวนแต้มที่เพิ่มเข้า
  "balance_after": 30             // ยอดแต้มสะสมคงเหลือปัจจุบัน
}
```
*เจ้าของร้าน (Owner) สามารถดูรายงานรวมยอด `loyalty_discount` ประจำเดือนเพื่อประเมินค่าใช้จ่ายทางการตลาด และผลกำไรที่แท้จริงได้ทันที*

## 🎯 เป้าหมาย

ยกระดับหน้าจอ **Owner Dashboard (`components/OwnerDashboard.tsx`)** ให้สามารถวิเคราะห์เชิงลึกทางการค้าและพฤติกรรมลูกค้าได้ดียิ่งขึ้น โดย:
1. ปรับเพิ่ม **Badge Switcher** ในการ์ดเดิม (จัดอันดับขายดี) ให้สลับดู **สัดส่วนหมวดหมู่ (Category Sales Breakdown)** ได้ในพื้นที่เดิม
2. เพิ่มการ์ดใหม่ **สถิติสมาชิก vs ลูกค้าทั่วไป (Member vs Non-Member Insights)** แทนที่ Void Summary เดิม
3. เพิ่มการ์ดใหม่ **สรุปช่องทางชำระเงิน & ส่วนลด (Payment Methods & Discounts Summary)** ในแถวถัดไป
4. ย้ายประวัติการยกเลิก (Void Summary) ให้เป็นปุ่ม/การ์ดย่อแบบเปิดดู Modal ได้ ไม่เสียพื้นที่แสดงผลหลัก

---

## 📋 รายละเอียดการ์ดแดชบอร์ด

### 1. การ์ดปรับปรุง: [จัดอันดับขายดี & สัดส่วนหมวดหมู่] (Top Sellers & Category Breakdown)

- **UI Element:** มี Badge Tabs บริเวณมุมขวาบนของการ์ด ให้ผู้ใช้คลิกสลับโหมดได้
  - `[ 🏆 รายการขายดี ]` (Default)
  - `[ 📊 สัดส่วนหมวดหมู่ ]`
- **โหมด 🏆 รายการขายดี:**
  - แสดง 5 อันดับแรกของรายการอาหารที่ขายดีที่สุด
  - แสดงอันดับ (1-5), ชื่อเมนู, จำนวนจานที่ขายได้ (`quantity`), ยอดขายรวม (`revenue` บาท)
- **โหมด 📊 สัดส่วนหมวดหมู่:**
  - รวมยอดขายและจำนวนจานที่ขายได้โดยกลุ่มตาม `menu_items.category` (เช่น เครื่องดื่ม, ของย่าง, ซาซิมิ, จานหลัก ฯลฯ)
  - แสดงชื่อหมวดหมู่, ยอดขายรวม (บาท), จำนวนจานรวม, และ **Progress Bar เปรียบเทียบ % ยอดขาย** ของแต่ละหมวดเทียบกับยอดขายรวม
  - คำนวณ % = `(ยอดขายหมวดหมู่ / ยอดขายสุทธิรวม) * 100`

---

### 2. การ์ดใหม่ 1: [สถิติสมาชิก vs ลูกค้าทั่วไป] (Member vs Non-Member Insights)

- **วัตถุประสงค์:** ประเมินประสิทธิภาพระบบ CRM/Loyalty และเปรียบเทียบพฤติกรรมการซื้อระหว่างสมาชิกกับลูกค้าทั่วไป
- **ข้อมูลที่แสดง:**
  1. **สัดส่วนยอดขาย (Sales Breakdown):**
     - ยอดขายจากสมาชิก (`phone_number IS NOT NULL`) ในรูปแบบ บาท และ %
     - ยอดขายจากลูกค้าทั่วไป (`phone_number IS NULL`) ในรูปแบบ บาท และ %
     - แถบเปรียบเทียบ visual bar สองสี (เช่น สีส้มสมาชิก vs สีฟ้าลูกค้าทั่วไป)
  2. **ยอดซื้อเฉลี่ยต่อบิล (Avg Spending / Bill):**
     - บิลสมาชิก = `ยอดขายรวมสมาชิก / จำนวนบิลสมาชิก`
     - บิลทั่วไป = `ยอดขายรวมทั่วไป / จำนวนบิลทั่วไป`
  3. **การใช้งานแต้มสะสม:**
     - แต้มสะสมที่ถูกใช้แลกเป็นส่วนลดในบิลรวม (`points_redeemed`)
     - มูลค่าส่วนลดรวมที่ลูกค้าแลกด้วยแต้ม (`points_redeemed * 1 บาท`)

---

### 3. การ์ดใหม่ 2: [สรุปช่องทางชำระเงิน & ส่วนลด] (Payment Methods & Discounts Summary)

- **วัตถุประสงค์:** ให้เจ้าของร้านตรวจสอบกระแสเงินสดตามช่องทางชำระเงินและสรุปต้นทุนส่วนลดที่ให้ลูกค้า
- **ข้อมูลที่แสดง:**
  1. **ช่องทางการชำระเงิน (Payment Methods):**
     - 💵 **เงินสด (Cash):** ยอดเงินรวม + จำนวนบิล
     - 📱 **PromptPay QR:** ยอดเงินรวม + จำนวนบิล
     - 🔀 **ชำระแบบผสม (Mixed):** ยอดเงินรวม + จำนวนบิล (แยกคำนวณเงินสด 50% + PromptPay 50%)
  2. **สรุปการให้ส่วนลด (Discount Metrics):**
     - ยอดขายก่อนลด (`subtotal` รวม)
     - ส่วนลดรวมทั้งหมดที่ให้ลูกค้า (`discount_amount` รวม)
     - ยอดขายสุทธิหลังหักส่วนลด (`net_amount` รวม)

---

### 4. การ์ดฉบับย่อ: [สรุปการยกเลิกรายการอาหาร (Void Audit Log)]

- **การปรับเปลี่ยน:** ปรับจากเดิมที่เป็นการ์ดใหญ่เต็มพื้นที่ ให้เป็นการ์ดขนาดกะทัดรัด
- **แสดงผล:**
  - ยอดรวมสูญเสียจาก Void (บาท) และ จำนวนครั้งที่ Void
  - ปุ่ม `[ 📋 ดูประวัติการยกเลิกทั้งหมด (X รายการ) ]` สำหรับเปิด Modal รายละเอียด Void Audit Log เหมือนเดิม

## 🗄️ Query & Data Processing (Supabase)

1. **`payments` Table Query:**
   ```typescript
   const { data: payData } = await supabase
     .from('payments')
     .select('payment_method, subtotal, discount_amount, net_amount, points_earned, points_redeemed, phone_number, created_at')
     .gte('created_at', startISO)
     .lte('created_at', endISO);
   ```
   - คำนวณ:
     - `memberRevenue`, `nonMemberRevenue`
     - `memberOrderCount`, `nonMemberOrderCount`
     - `avgMemberSpend`, `avgNonMemberSpend`
     - `cashTotal`, `promptpayTotal`, `mixedTotal`
     - `totalDiscountAmount`, `totalPointsRedeemed`

2. **`order_items` Table Query:**
   ```typescript
   const { data: salesData } = await supabase
     .from('order_items')
     .select('quantity, unit_price, discount_applied, status, created_at, menu_items(name, category)')
     .eq('status', 'served')
     .gte('created_at', startISO)
     .lte('created_at', endISO);
   ```
   - คำนวณ:
     - `topSellers`: จัดกลุ่มตาม `menu_items.name`
     - `categoryBreakdown`: จัดกลุ่มตาม `menu_items.category` (คำนวณ `revenue` และ `%` ของยอดขายรวม)

## 🧪 Verification Plan

1. **Category Breakdown Tab:** ลองกดสลับแท็บ `[🏆 รายการขายดี]` และ `[📊 สัดส่วนหมวดหมู่]` ในการ์ดเมนูขายดี ดูว่าแสดงผลสัดส่วน % และ Progress bar ถูกต้อง
2. **Member vs Non-Member:** ลองทำรายการชำระเงินแบบใส่เบอร์สมาชิกและไม่ใส่เบอร์ ตรวจสอบว่ายอดเงินเฉลี่ยต่อบิลและ % สัดส่วนคำนวณถูก
3. **Payment Methods & Discounts:** ลองชำระเงินด้วยเงินสด, PromptPay, และใส่ส่วนลด ตรวจสอบว่าตัวเลขเงินสด/โอน/ส่วนลดรวมตรงกับความเป็นจริง
4. **Build Verification:** `pnpm build` ผ่านสมบูรณ์ ไม่มี TypeScript errors

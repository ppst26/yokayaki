## 🎯 เป้าหมาย

สร้างหน้าจอ **จัดการพนักงาน (Employee Management)** สำหรับ Owner ให้สามารถเพิ่ม ลบ แก้ไขข้อมูลพนักงานในร้านได้ทั้งหมด โดยมีระบบยืนยัน PIN ก่อนทำ action สำคัญ

---

## 📋 ฟังก์ชันที่ต้องการ

| ฟังก์ชัน | รายละเอียด | ต้องยืนยัน PIN |
|----------|-----------|:-------------:|
| **เพิ่มพนักงานใหม่** | กรอกชื่อ + PIN 6 หลัก + เลือก Role (owner/staff) | ❌ |
| **ลบพนักงาน** | ลบออกจากระบบถาวร (**ห้ามลบตัวเอง**) | ✅ |
| **แก้ไขชื่อ** | เปลี่ยนชื่อแสดงผลของพนักงาน | ❌ |
| **เปลี่ยน PIN** | ตั้ง PIN 6 หลักใหม่ (SHA-256 hash ก่อนบันทึก) | ❌ |
| **เปลี่ยน Role** | สลับ owner ↔ staff | ✅ |

> **หมายเหตุ:** "ต้องยืนยัน PIN" หมายถึง Owner ที่ล็อกอินอยู่ต้องกรอก PIN ของตัวเองอีกครั้งก่อนดำเนินการ

## 🏗️ Architecture

### แนวทาง: RPC-based (SECURITY DEFINER)

ใช้ Supabase RPC functions ตาม pattern เดียวกับ `place_order_item`, `complete_checkout` ฯลฯ ไม่เปิด RLS write policy ของตาราง `employees` เพิ่ม เพื่อความปลอดภัย

#### SQL RPC Functions (3 ฟังก์ชัน)

##### 1. `add_employee(p_name, p_pin_hash, p_role)`
- **Input:** ชื่อ, PIN hash (SHA-256 ที่ hash จาก client), role ('owner'/'staff')
- **Logic:**
  1. ตรวจสอบว่า `p_role` ถูกต้อง (`owner` หรือ `staff` เท่านั้น)
  2. ตรวจสอบว่า `p_name` ไม่ว่าง
  3. ตรวจสอบว่า `p_pin_hash` ไม่ซ้ำกับพนักงานคนอื่น (ป้องกัน PIN ชน)
  4. INSERT เข้าตาราง `employees`
  5. RETURN id ของพนักงานใหม่ (หรือ -1 ถ้าซ้ำ)

##### 2. `update_employee(p_employee_id, p_name, p_pin_hash, p_role)`
- **Input:** ID พนักงานที่จะแก้ไข, ชื่อใหม่ (หรือ null ถ้าไม่เปลี่ยน), PIN hash ใหม่ (หรือ null ถ้าไม่เปลี่ยน), role ใหม่ (หรือ null ถ้าไม่เปลี่ยน)
- **Logic:**
  1. ตรวจสอบว่าพนักงาน `p_employee_id` มีอยู่จริง
  2. ถ้า `p_pin_hash` ไม่ใช่ null → ตรวจสอบว่าไม่ซ้ำกับคนอื่น
  3. ถ้า `p_name` ไม่ใช่ null → UPDATE name
  4. ถ้า `p_pin_hash` ไม่ใช่ null → UPDATE pin_hash
  5. ถ้า `p_role` ไม่ใช่ null → UPDATE role
  6. RETURN TRUE ถ้าสำเร็จ

##### 3. `delete_employee(p_employee_id, p_requester_pin_hash)`
- **Input:** ID พนักงานที่จะลบ, PIN hash ของ Owner ที่ทำรายการ
- **Logic:**
  1. ตรวจสอบว่า `p_requester_pin_hash` ตรงกับ Owner คนใดคนหนึ่งในระบบ
  2. ตรวจสอบว่า Owner ไม่ได้กำลังลบตัวเอง (เทียบ pin_hash)
  3. ตรวจสอบว่าพนักงาน `p_employee_id` มีอยู่จริง
  4. DELETE จากตาราง `employees`
  5. RETURN TRUE ถ้าสำเร็จ

> ⚠️ **สำคัญ:** ฟังก์ชัน `update_employee` ไม่ต้องยืนยัน PIN ที่ฝั่ง RPC — เพราะ PIN confirmation จะทำที่ฝั่ง client UI เฉพาะ action "เปลี่ยน Role" เท่านั้น (เปลี่ยนชื่อ/PIN ไม่ต้องยืนยัน)

## 🔒 Security Considerations

1. **RPC ทั้ง 3 ฟังก์ชันเป็น `SECURITY DEFINER`** — ทำงานด้วยสิทธิ์เจ้าของฟังก์ชัน ไม่ใช่ anon key
2. **PIN Hash ทำที่ client ก่อนส่ง** — ใช้ `hashPin()` จาก AuthContext (SHA-256)
3. **ลบพนักงาน: ตรวจสิทธิ์ซ้ำที่ server** — `delete_employee` ต้องรับ `p_requester_pin_hash` มาเทียบว่าเป็น Owner จริง
4. **ห้ามลบตัวเอง** — ป้องกันใน RPC โดยเทียบ pin_hash ของ requester กับ employee ที่จะลบ
5. **PIN ซ้ำ** — ป้องกันไม่ให้มี PIN เดียวกัน 2 คน (ทำให้ login ผิดคน)
6. **ไม่เปิด RLS write policy เพิ่ม** — ตาราง employees ยังคง read-only สำหรับ public, write ผ่าน RPC เท่านั้น

## 🔄 Data Flow

### เพิ่มพนักงาน
```
Owner กรอกฟอร์ม (ชื่อ + PIN + Role)
  → Client: validate PIN 6 หลัก + ตรงกัน 2 ช่อง
  → Client: hashPin(PIN) → SHA-256
  → RPC: add_employee(name, pin_hash, role)
  → Server: validate + INSERT
  → Client: refetch employee list + แสดง success toast
```

### ลบพนักงาน
```
Owner กดปุ่ม "ลบ" บนการ์ดพนักงาน
  → PIN Confirmation Dialog เปิดขึ้น
  → Owner กรอก PIN 6 หลักของตัวเอง
  → Client: hashPin(PIN) → SHA-256
  → RPC: delete_employee(employee_id, owner_pin_hash)
  → Server: verify owner + check ≠ self + DELETE
  → Client: refetch + แสดง success toast
```

### เปลี่ยน Role
```
Owner กดปุ่ม "เปลี่ยน Role" บนการ์ดพนักงาน
  → PIN Confirmation Dialog เปิดขึ้น
  → Owner กรอก PIN 6 หลักของตัวเอง
  → Client: hashPin(PIN) → verify locally ว่าเป็น owner จริง
  → RPC: update_employee(employee_id, null, null, new_role)
  → Server: validate + UPDATE role
  → Client: refetch + แสดง success toast
```

## 🧪 Verification Plan

### Manual Testing
1. **เพิ่มพนักงาน:** กรอกชื่อ + PIN + เลือก role → ดูว่าปรากฏในรายชื่อ
2. **PIN ซ้ำ:** พยายามเพิ่มพนักงานด้วย PIN ที่ซ้ำกับคนอื่น → ต้องแสดง error
3. **ลบพนักงาน:** กด ลบ → กรอก PIN Owner → ดูว่าหายจากรายชื่อ
4. **ลบตัวเอง:** กด ลบ ตัวเอง → ต้องแสดง error "ไม่สามารถลบตัวเองได้"
5. **แก้ไขชื่อ:** กดแก้ไข → เปลี่ยนชื่อ → ดูว่าอัปเดตทันที
6. **เปลี่ยน PIN:** กดเปลี่ยน PIN → กรอก PIN ใหม่ → ลองล็อกเอาท์แล้วล็อกอินด้วย PIN ใหม่
7. **เปลี่ยน Role:** กดเปลี่ยน Role → กรอก PIN Owner → ดูว่า badge เปลี่ยน
8. **ยืนยัน PIN ผิด:** กรอก PIN ผิดใน confirmation dialog → ต้องแสดง error

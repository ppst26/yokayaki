# Specification: Payment & Checkout Design (payment-design.md)

เอกสารรายละเอียดการออกแบบระบบชำระเงิน, ลอจิกการคำนวณยอดบิลแบบผสม (Multi-Payment), การสร้างรหัส Dynamic PromptPay QR และขั้นตอนการปิดเซสชันโต๊ะ (Close Table) สำหรับร้าน Yokayaki Izakaya

---

## 1. ขั้นตอนการเช็คบิลเรียกเก็บเงิน (Checkout Workflow)

กระบวนการคิดเงินจะถูกควบคุมผ่านพนักงานที่เครื่อง POS หลักของร้านเท่านั้น เพื่อความปลอดภัยสูงสุดและป้องกันความเข้าใจผิดเรื่องยอดเงิน

### 1.1 ลำดับขั้นตอนการทำงาน (Step-by-Step Flow)

```
[ลูกค้ากดเรียกเช็คบิล/บอกพนักงาน] ➡️ [โต๊ะเปลี่ยนเป็นสีเหลืองบนผัง] ➡️ [พนักงานเปิดหน้าบิลบน POS] ➡️ [เลือกช่องทางจ่ายเงิน] ➡️ [ตรวจสอบยอด/สลิป] ➡️ [ยืนยันรับเงิน] ➡️ [ระบบเคลียร์โต๊ะและเซสชันอัตโนมัติ]
```

### 1.2 ตัวอย่างสถานการณ์จริง (Use Case Scenario)
*   **สถานการณ์:** ลูกค้านั่งโต๊ะ 3 ทานเสร็จเรียบร้อยและต้องการชำระเงิน
*   **ขั้นตอนที่ 1 (ฝั่งลูกค้า):** ลูกค้ากดปุ่ม "เรียกเช็คบิล (Bill Check)" บนโทรศัพท์ของตนเอง 
*   **ขั้นตอนที่ 2 (ฝั่งพนักงาน):** หน้าจอผังโต๊ะหลักของร้านจะแสดงภาพโต๊ะ 3 กะพริบเป็น **สีเหลือง (Check-out Pending)** พนักงานเดินไปที่โต๊ะเพื่อยืนยันออเดอร์กับลูกค้า หรือลูกค้าเดินมาที่แคชเชียร์
*   **ขั้นตอนที่ 3 (ฝั่งพนักงาน):** พนักงานกดเลือกโต๊ะ 3 บน POS หน้าจอจะแสดงรายการสรุปบิลปัจจุบัน:
    *   ยากิโทริสะโพกไก่ย่างเกลือ x 4 ไม้ = `160 บาท`
    *   เบียร์สดโอกินาว่า x 2 แก้ว = `180 บาท`
    *   นาเบะหม้อไฟหมูสามชั้น x 1 ชุด = `320 บาท`
    *   **ยอดรวมทั้งหมด (Subtotal) = 660 บาท** *(คิดราคาเน็ต ไม่มี Vat/Service Charge แฝงเพื่อความง่ายสำหรับร้านขนาดเล็ก)*
*   **ขั้นตอนที่ 4 (ฝั่งพนักงาน):** พนักงานกดยืนยันตรวจเช็ครายการอาหารร่วมกับลูกค้าบนจอ แล้วกดปุ่ม **"ชำระเงิน (Checkout)"** เพื่อเปิดหน้าต่างรับเงิน

## 2. ระบบชำระเงินแบบผสม (Multi-Payment) และ Dynamic PromptPay QR

ระบบของ Yokayaki ออกแบบมารองรับรูปแบบพฤติกรรมยอดฮิตของลูกค้าไทย คือการจ่ายเงินสดบางส่วนและโอนเงินในส่วนที่เหลือ เพื่อจัดการเศษเงินทอนที่วุ่นวาย

### 2.1 หน้าจอคำนวณ Multi-Payment (ฝั่งพนักงาน)
ระบบ POS จะมีช่องอินพุตรับเงิน 2 ประเภทหลักพร้อมปุ่มคำนวณเงินทอน/เงินโอนอัตโนมัติ

#### 📥 กรณีที่ 1: ชำระเงินสดเต็มจำนวน (100% Cash)
*   **ตัวอย่าง:** ยอดบิลรวม `660 บาท` ลูกค้าจ่ายแบงก์ 1,000 บาท
*   *การคำนวณ:* พนักงานป้อนเงินสดรับ = `1000` บาท
*   *ผลลัพธ์บนจอ:* ระบบคำนวณเงินทอนอัตโนมัติ ➡️ `เงินทอน = 1,000 - 660 = 340 บาท` พนักงานคืนเงินทอน 340 บาทและกดบันทึก

#### 📥 กรณีที่ 2: ชำระเงินโอนเต็มจำนวน (100% Transfer)
*   **ตัวอย่าง:** ยอดบิลรวม `660 บาท` ลูกค้าต้องการโอนจ่ายทั้งหมด
*   *การคำนวณ:* พนักงานกดปุ่ม "โอนเงินเต็มจำนวน"
*   *ผลลัพธ์บนจอ:* ระบบป้อนช่องเงินโอนรับอัตโนมัติ = `660` บาท และสร้าง Dynamic QR สำหรับยอดเงิน **660 บาท** ทันที

#### 📥 กรณีที่ 3: จ่ายเงินสดผสมเงินโอน (Mixed Payment)
*   **ตัวอย่าง:** ยอดบิลรวม `660 บาท` ลูกค้ายื่นแบงก์ 100 บาทให้พนักงาน 1 ใบ และที่เหลือขอสแกนโอน
*   *การคำนวณ:*
    1. พนักงานป้อนเงินสดรับ = `100` บาท
    2. ระบบคำนวณยอดค้างชำระให้อัตโนมัติ: `ยอดค้างชำระ = 660 - 100 = 560 บาท`
    3. พนักงานกดปุ่ม **"สร้าง Dynamic QR ยอดคงเหลือ"**
    4. หน้าจอจะเด้งป๊อปอัปแสดง QR Code ที่ระบุมูลค่าเงินโอน **560 บาท** พอดีเป๊ะ

---

### 2.2 โครงสร้างและคุณสมบัติของ Dynamic PromptPay QR

*   **รหัส EMVCo ใต้ภาพ:** เบื้องหลังภาพ QR Code จะเป็นชุดอักขระข้อความมาตรฐาน เช่น:
    `00020101021229300016A000000677010111011300668999999995802TH5406560.0053037646304E85C`
    *(อักขระตัวอย่างนี้ฝังเบอร์พร้อมเพย์ร้าน และระบุจำนวนเงินเจาะจงที่ `560.00` บาทไว้ในรหัสอย่างถาวร)*
*   **การใช้งานหน้าร้าน:** พอลูกค้าสแกน QR Code นี้จากหน้าจอ POS ด้วยแอปธนาคารใดๆ:
    1. หน้าจอโอนเงินจะเด้งชื่อร้าน **"Yokayaki Izakaya"** ทันที
    2. ช่องจำนวนเงินจะขึ้นตัวเลข **"560.00 บาท"** ให้โดยอัตโนมัติโดยที่ลูกค้ากดแก้ไขตัวเลขไม่ได้
    3. ลูกค้าตรวจสอบชื่อและยอด แล้วกดยืนยันรหัสผ่านเพื่อโอนเงินได้เลย
*   **ข้อดีด้านความปลอดภัย:**
    *   ป้องกันลูกค้าเมาแล้วกดจำนวนเงินขาดหรือเกิน (เช่น จ่าย 560 แต่คีย์เลขผิดเป็น 56 หรือ 5600)
    *   ลดเวลาในการยืนยันสลิป พนักงานเพียงตรวจสอบชื่อผู้โอนและเวลาในสลิปให้ตรงก็ผ่านได้ทันที
    *   **ไม่ส่ง QR นี้ขึ้นจอมือถือลูกค้า:** ลูกค้าต้องสแกนจากเครื่อง POS หน้าร้านหรือเครื่องแท็บเล็ตที่พนักงานถือมาเท่านั้น เพื่อบังคับให้พนักงานอยู่ต่อหน้าลูกค้าตลอดการคิดเงิน

## 3. การปิดโต๊ะและการพิมพ์ใบเสร็จดิจิทัล (E-Receipt)

เมื่อตรวจสอบเงินสดในมือครบ หรือเช็คสลิปการโอนเงินว่าเข้าบัญชีเรียบร้อย พนักงานจะกดปุ่ม **"ยืนยันรับชำระเงิน (Confirm Payment)"** บน POS ซึ่งจะส่งผลให้ระบบทำงานดังต่อไปนี้:

### 3.1 การปิดโต๊ะบนฐานข้อมูล (Database Execution Example)
เมื่อระบบได้รับคำสั่งยืนยันการรับเงิน จะทำการอัปเดตฐานข้อมูล Supabase ทันที:
1.  **ตาราง `qr_sessions`:** อัปเดตสถานะของโต๊ะนั้นเป็น `status = 'inactive'` และบันทึกเวลาสิ้นสุด `ended_at = NOW()`
    *   *ผลลัพธ์:* ลูกค้าสแกนคิวอาร์เดิมบนโต๊ะจะไม่สามารถแก้ไขตะกร้าหรือส่งออเดอร์ใหม่ได้อีก ระบบจะขึ้นแจ้งเตือนว่า *"เซสชันนี้สิ้นสุดลงแล้ว ขอบคุณค่ะ"*
2.  **ตาราง `tables`:** ปรับสถานะโต๊ะกลับเป็น `status = 'vacant'`
    *   *ผลลัพธ์:* หน้าจอผังโต๊ะของพนักงานจะเปลี่ยนกลับเป็น **สีเขียว (โต๊ะว่าง)** พร้อมต้อนรับลูกค้ากลุ่มถัดไป
3.  **ตาราง `payments`:** เพิ่มรายการธุรกรรมใหม่ เช่น:
    *   `order_id`: "ORD-20260705-003"
    *   `payment_method`: "MIXED"
    *   `cash_amount`: 100.00
    *   `transfer_amount`: 560.00
    *   `total_amount`: 660.00
    *   `created_at`: "2026-07-05 21:20:00"

---

### 3.2 ใบเสร็จดิจิทัลและการพิมพ์ (Digital Receipt & Browser-Native Print)

หลังปิดโต๊ะสำเร็จ หน้าจอ POS จะแสดงบิลใบเสร็จดิจิทัลสรุปรายการสุดท้าย ตัวอย่างเลย์เอาต์ดังนี้:

```
      YOKAYAKI IZAKAYA
      (3-4 Tables Setup)
================================
บิลเลขที่: ORD-20260705-003
โต๊ะที่: Table 3
วันที่: 05-07-2026  เวลา: 21:20 น.
--------------------------------
- ยากิโทริสะโพกไก่ x 4      160 บาท
- เบียร์สดโอกินาว่า x 2     180 บาท
- นาเบะหม้อไฟหมู x 1       320 บาท
--------------------------------
รวมทั้งสิ้น:                660 บาท
ชำระโดย:
  * เงินสด:                100 บาท
  * โอนพร้อมเพย์:           560 บาท
--------------------------------
      ขอบคุณที่ใช้บริการค่ะ!
```

*   **ฟังก์ชันการพิมพ์:** หน้านี้จะใช้ระบบจัดวางหน้าพิเศษ (Print-friendly CSS `@media print`) ซึ่งพนักงานสามารถกดปุ่ม **"พิมพ์ใบเสร็จ (Print Receipt)"** จากนั้นหน้าต่างพิมพ์ด่วนของเบราว์เซอร์จะเด้งขึ้นมา
*   ระบบ CSS จะซ่อนแถบเมนูนำทาง ปุ่มกดสีต่างๆ ออกทั้งหมด เหลือเฉพาะบล็อกบิลทรงสี่เหลี่ยมแนวยาวนี้ขนาดกว้าง 80mm สำหรับส่งพิมพ์ออกทางเครื่องพิมพ์ความร้อนแบบตั้งโต๊ะทั่วไปได้ทันที โดยไม่ต้องยุ่งยากกับการเชื่อมต่อผ่านบลูทูธหรือไดรเวอร์เชิงลึกค่ะ

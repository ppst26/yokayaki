## 🎯 1. ภาพรวมระบบ (Overview)

ระบบ **Sales & Audit History + Void Logs** ถูกออกแบบมาเพื่อเป็น **เครื่องมือตรวจสอบความถูกต้องของการปฏิบัติงานหน้าร้าน (Front-of-House Operational Audit)** สำหรับพนักงานแคชเชียร์ ผู้จัดการร้าน และเจ้าของร้าน 

วัตถุประสงค์หลักคือ:
1. **ตรวจสอบความถูกต้องของการชำระเงิน:** ดูรายการบิลที่เช็คแล้ว แก้อุปสรรคกรณีคิดเงินผิด ทอนเงินผิด หรือพิมพ์ใบเสร็จย้ำ (Reprint Receipt)
2. **ป้องกันการทุจริต (Audit Trail):** บันทึกประวัติการยกเลิกออเดอร์ (Void) ทุกรายการอย่างรวดเร็วและโปร่งใส พร้อมระบุเหตุผลและผู้ทำรายการ
3. **การประมวลผลความเร็วสูง (High Performance):** ออกแบบให้เลือกดูย้อนหลังช่วงสั้นๆ ได้แก่ **"วันนี้ (Today)"** และ **"เมื่อวาน (Yesterday)"** เพื่อให้ระบบทำงานรวดเร็วในระดับมิลลิวินาที ไม่เบียดบังระบบรายงานใหญ่

## 🗄️ 3. โครงสร้างฐานข้อมูลที่เกี่ยวข้อง (Database Schemas & RPCs)

### 3.1 ตารางฐานข้อมูล (Tables)

| ตาราง | คำอธิบาย | คอลัมน์สำคัญ |
|-------|----------|--------------|
| `orders` | หัวข้อออเดอร์ | `id`, `table_id`, `status` ('completed'/'voided'), `created_at` |
| `order_items` | รายการอาหารย่อย | `id`, `order_id`, `menu_item_id`, `quantity`, `unit_price`, `status`, `notes` |
| `payments` | บันทึกธุรกรรมชำระเงิน | `id`, `order_id`, `payment_method`, `subtotal`, `discount_amount`, `net_amount`, `cash_amount`, `promptpay_amount`, `points_earned`, `points_redeemed`, `phone_number` |
| `payment_promotions` | โปรโมชั่นที่ถูกใช้ในบิล | `id`, `payment_id`, `promotion_name`, `promotion_type`, `discount_value`, `free_items` |
| `void_logs` | บันทึกประวัติการ Void (Audit Log) | `id`, `order_item_id`, `employee_name`, `menu_name`, `quantity`, `total_amount`, `reason`, `restored_stock`, `created_at` |

### 3.2 ฟังก์ชัน RPC สำคัญ (`void_order_item`)
ฟังก์ชัน `SECURITY DEFINER` สำหรับการยกเลิกออเดอร์อย่างปลอดภัย:
- **Parameters:** `(p_order_item_id, p_employee_name, p_reason, p_restore_stock)`
- **การทำงาน:**
  1. อัปเดต `order_items.status = 'voided'`
  2. หาก `p_restore_stock = true` และเมนูนั้นตั้งค่า `is_stock_tracked = true` ระบบจะคืนสต็อกวัตถุดิบ/เมนูโดยอัตโนมัติ
  3. บันทึกประวัติลงตาราง `void_logs` แบบ Atomic Transaction

## 🔄 4. รายละเอียดฟีเจอร์และการใช้งาน (Features & Workflow)

### 4.1 ฟิลเตอร์สลับช่วงเวลา audit (`Today` vs `Yesterday`)
- **วันนี้ (Today):** ดึงข้อมูลออเดอร์และ Void Logs ตั้งแต่ `00:00:00` ถึง `23:59:59` ของวันปัจจุบัน
- **เมื่อวาน (Yesterday):** ดึงข้อมูลย้อนหลัง 1 วัน เหมาะสำหรับตรวจสอบบิลรอบเมื่อคืน หรือกรณีลูกค้าร้องเรียนทอนเงินผิดของเมื่อวาน
- **การอัปเดตแบบเรียลไทม์:** เมื่อเปลี่ยนช่วงเวลา การ์ดสรุปยอด ตารางบิล และตาราง Void จะถูกคำนวณใหม่ทันที

### 4.2 แท็บ 1: รายการขาย (Completed Sales)
- แสดงสถิติภาพรวม 4 การ์ด: **ยอดขายสุทธิ**, **ส่วนลดรวมทั้งหมด**, **จำนวนบิลที่เปิดบิลแล้ว**, **รายการถูก Void ยกเลิก**
- ตารางแสดงรายการบิล เรียงลำดับจากล่าสุดลงไป
- เมื่อคลิกที่บิล จะเปิด **BillDetailModal** เพื่อดู:
  - รายการอาหารทุกจาน พร้อมราคาและโน้ตพิเศษ
  - โปรโมชั่น/คูปองที่ใช้ในบิลนั้น
  - ข้อมูลสมาชิก CRM, แต้มสะสมที่ได้รับ และแต้มที่ใช้แลก
  - ช่องทางชำระเงิน (เงินสด / PromptPay QR / ผสม)
  - **ปุ่มพิมพ์ใบเสร็จ (Print Receipt):** พิมพ์ใบเสร็จย่อยขนาด 80mm Thermal Printer ได้ทันที

### 4.3 แท็บ 2: ประวัติการ Void ยกเลิกรายการ (Void Logs)
- บันทึกทุกครั้งที่มีการยกเลิกรายการอาหารโดยพนักงานหรือผู้จัดการ
- **ข้อมูลที่แสดงในตาราง:**
  - `เวลา`: เวลาที่เกิดการ Void
  - `รายการอาหาร`: ชื่อเมนูที่ถูกยกเลิก
  - `จำนวน`: จำนวนจานที่ยกเลิก
  - `มูลค่า Void`: จำนวนเงินที่สูญเสีย/ยกเลิกไป (`quantity * unit_price`)
  - `เหตุผลในการ Void`: เช่น ทำอาหารผิด, ลูกค้าเปลี่ยนใจ, คีย์ออเดอร์ซ้ำ
  - `สถานะสต็อก`: แสดงสัญลักษณ์ว่ารายการนี้ถูก **"คืนสต็อก"** เข้าครัว หรือ **"ไม่คืนสต็อก"** (กรณีวัตถุดิบเสีย/ทิ้ง)
  - `ผู้ทำรายการ`: ชื่อพนักงาน/เจ้าของร้านที่ป้อน PIN อนุมัติการ Void

## 🔒 5. สิทธิ์และการรักษาความปลอดภัย (Security & Authorization)

1. **สิทธิ์การเข้าถึงหน้า Sales & Audit History:**
   - **Owner (เจ้าของร้าน):** เข้าถึงได้เต็มรูปแบบ
   - **Staff (พนักงาน):** เข้าถึงได้เพื่อตรวจสอบประวัติและพิมพ์ใบเสร็จย้ำ
2. **สิทธิ์การสั่ง Void รายการ:**
   - การสั่ง Void ในหน้า POS Order ต้องยืนยันสิทธิ์ผ่าน PIN Code เสมอ เพื่อป้องกันพนักงานแอบยกเลิกออเดอร์แล้วเก็บเงินสดเข้ากระเป๋า

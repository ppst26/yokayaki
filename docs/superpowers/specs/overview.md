# Project Overview: Yokayaki Izakaya POS

เอกสารภาพรวมระบบระบบ POS ร้านอาหารสไตล์อิซากายะขนาดเล็ก (3-4 โต๊ะ) โฟกัสการทำงานที่รวดเร็ว ลื่นไหล ป้องกันเงินรั่วไหล และมีความคล่องตัวสูง

---

## 1. คอนเซ็ปต์หลัก (Core Concept)
ระบบ POS ที่ทำงานแบบ **"ไฮบริด (Hybrid)"** รองรับการรับออเดอร์จากสองทิศทางพร้อมกัน:
1. **Staff Terminal:** พนักงานหน้าร้านสั่งผ่านหน้าจอ POS หลักของร้าน
2. **QR Order:** ลูกค้าใช้โทรศัพท์ส่วนตัวสแกน QR Code ประจำโต๊ะเพื่อเลือกดูเมนูและสั่งอาหารด้วยตัวเอง

---

## 2. ขอบเขตของร้านค้าและเป้าหมาย (Scope & Target)
* **ขนาดร้าน:** 3-4 โต๊ะ (เน้นร้านอิซากายะหรือร้านอาหารขนาดเล็ก-กลาง)
* **ผู้ใช้งานหลัก:** 
  * **Owner:** เจ้าของร้าน ดูแลยอดขาย สต็อก ราคาสินค้า
  * **Staff:** พนักงานต้อนรับ รับออเดอร์ ทำความสะอาดโต๊ะ และคิดเงิน
* **ความปลอดภัย:** ระบบใช้รหัส PIN 6 หลักในการยืนยันสิทธิ์พนักงานแต่ละคน และใช้ Supabase RLS ในการป้องกันข้อมูลทางการเงินรั่วไหล

---

## 3. โครงสร้างเทคโนโลยี (Tech Stack)
* **Frontend:** Next.js (App Router, Tailwind CSS, shadcn/ui)
* **Backend:** Next.js Server Actions / API Routes
* **Database & Real-time:** Supabase (PostgreSQL, Supabase Realtime สำหรับส่งข้อมูลออเดอร์เข้าครัว และ Row Level Security - RLS)
* **Deployment:** Vercel (หรือตามต้องการ)

---

## 4. แผนผังฐานข้อมูลเบื้องต้น (Database Schema Overview)
ความสัมพันธ์ของข้อมูลจะถูกเชื่อมต่อกันผ่านตารางหลักๆ ดังนี้:
* `employees` ➡️ จัดเก็บสิทธิ์และรหัส PIN 6 หลัก
* `tables` ➡️ จัดเก็บผังโต๊ะและสถานะความว่าง
* `qr_sessions` ➡️ ควบคุมเซสชันสั่งอาหารแบบไดนามิกของลูกค้า
* `menu_items` ➡️ จัดเก็บข้อมูลราคาและสต็อกสินค้าของร้าน
* `orders` & `order_items` ➡️ ข้อมูลออเดอร์ประวัติการสั่งอาหาร
* `void_logs` ➡️ บันทึกการยกเลิกรายการอาหารโดยละเอียด
* `payments` ➡️ ข้อมูลธุรกรรมบิลแต่ละใบ

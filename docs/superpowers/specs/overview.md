# Project Overview: Yokayaki Izakaya POS

เอกสารภาพรวมระบบระบบ POS ร้านอาหารสไตล์อิซากายะขนาดเล็ก (3-4 โต๊ะ) โฟกัสการทำงานที่รวดเร็ว ลื่นไหล ป้องกันเงินรั่วไหล และมีความคล่องตัวสูง

---

## 1. คอนเซ็ปต์หลัก (Core Concept)

ระบบ POS ที่ทำงานแบบ **"ไฮบริด (Hybrid)"** รองรับการรับออเดอร์จากสองทิศทางพร้อมกัน เพื่อให้เกิดความลื่นไหลสูงสุด ลดการคอขวดที่แคชเชียร์ และช่วยประหยัดเวลาของพนักงาน:

1.  **Staff Terminal (พนักงานเป็นผู้สั่ง):** พนักงานคีย์อาหารผ่านเครื่องแท็บเล็ต/POS ส่วนกลางของร้าน
2.  **QR Order (ลูกค้าสแกนสั่งเอง):** ลูกค้าใช้สมาร์ทโฟนของตัวเองสแกน QR Code ประจำโต๊ะเพื่อดูเมนูรูปภาพและกดสั่งอาหารเข้าครัวได้โดยตรง

### 💡 ตัวอย่างสถานการณ์การทำงานแบบไฮบริด (Hybrid Scenario Example)
*   **โต๊ะที่ 1 (กลุ่มวัยรุ่น):** เดินเข้ามานั่งที่โต๊ะ พนักงานเปิดโต๊ะบน POS และให้ลูกค้าสแกน QR ลูกค้ากดเลือกสั่ง "เบียร์สด 4 แก้ว" และ "ไก่ทอดคาราเกะ" ด้วยตัวเองผ่านมือถือ ออเดอร์ยิงตรงเข้าครัวทันที พนักงานไม่ต้องเดินไปรับออเดอร์
*   **โต๊ะที่ 2 (ลูกค้าผู้ใหญ่):** ไม่ถนัดเทคโนโลยี ขอสั่งอาหารกับพนักงานโดยตรง พนักงานเดินไปรับออเดอร์แล้วกดคีย์เมนู "แก้มปลาต้มซีอิ๊ว" และ "สาเกร้อน" ลงเครื่อง POS ส่วนกลาง ออเดอร์ยิงตรงเข้าครัวเช่นกัน
*   **ผลลัพธ์หลังบ้าน:** ครัวเห็นรายการของทั้งสองโต๊ะเรียงตามลำดับก่อน-หลัง (FIFO) บนจอเดียวกัน และพนักงานสามารถกดดูยอดเงินรวมของทั้งสองโต๊ะได้จากเครื่อง POS หลักเครื่องเดียว

## 2. ขอบเขตของร้านค้าและเป้าหมาย (Scope & Target)

ออกแบบสำหรับร้านอาหารสเกลเล็กเพื่อลดทอนฟีเจอร์ที่ไม่จำเป็นออก (ตามหลัก YAGNI) เน้นความคล่องตัวและใช้งานง่าย

*   **ขนาดร้าน:** 3-4 โต๊ะ
    *   *คำอธิบาย:* เนื่องจากร้านมีขนาดเล็กมาก พนักงานหน้าร้าน (มักมี 1-2 คน) และครัวจะอยู่ใกล้ชิดกัน การสื่อสารสามารถทำได้รวดเร็ว ระบบจึงเน้นความเรียบง่ายแต่เหนียวแน่นในการบันทึกบัญชีและการคุมยอด
*   **ผู้ใช้งานหลัก (Primary Users):**
    *   **👑 OWNER (เจ้าของร้าน):**
        *   *หน้าที่:* ดูแลภาพรวมยอดขาย ปรับราคาสินค้า ควบคุมสต็อก และตรวจสอบการยกเลิกอาหาร (Void Logs) ป้องกันพนักงานทุจริต
        *   *ตัวอย่าง:* พี่พี (Owner) เปิดดูหน้าจอ Dashboard ยอดขายรายชั่วโมงจากโทรศัพท์มือถือขณะอยู่นอกร้าน และกดปรับราคากลางวันของ "ซาชิมิแซลมอน" เป็นราคาโปรโมชัน Happy Hour ได้ทันที
    *   **💁‍♂️ STAFF (พนักงานหน้าร้าน):**
        *   *หน้าที่:* ต้อนรับลูกค้า, เปิดโต๊ะ, นำส่ง QR ให้ลูกค้าสแกน, คีย์อาหารเสริม, บริการเสิร์ฟ และเช็คบิลปิดโต๊ะ
        *   *ตัวอย่าง:* น้องพนักงานคีย์เบอร์โทรศัพท์ของลูกค้าสมาชิกในหน้าเช็คบิลเพื่อสะสมแต้ม หักคะแนนแลกส่วนลด และสแกนสลิปโอนเงินยืนยันก่อนกดยืนยันปิดโต๊ะ 3 ให้เป็นโต๊ะว่าง
*   **ความปลอดภัย (Security Rules):**
    *   *คำอธิบาย:* ระบบใช้รหัส **PIN Code 6 หลัก** ในการสลับผู้ใช้งานหน้า POS หลักอย่างรวดเร็ว โดยจะล็อกการเข้าถึงฟังก์ชันสำคัญ
    *   *ตัวอย่าง:* พนักงานทั่วไป (Staff) จะกดดูหน้ารายงานยอดขายรวมของร้านไม่ได้ หากพยายามกด ระบบจะแสดงหน้าต่างล็อกความปลอดภัยและเตือนว่า *"ต้องการสิทธิ์ผู้จัดการ (Owner) กรุณากรอกรหัส PIN 6 หลักเพื่ออนุมัติ"*

## 3. โครงสร้างเทคโนโลยี (Tech Stack)
* **Frontend:** Next.js (App Router, Tailwind CSS, shadcn/ui)
* **Backend:** Next.js Server Actions / API Routes
* **Database & Real-time:** Supabase (PostgreSQL, Supabase Realtime สำหรับส่งข้อมูลออเดอร์เข้าครัว และ Row Level Security - RLS)
* **Deployment:** Vercel (หรือตามต้องการ)

---

## 4. แผนผังฐานข้อมูลเบื้องต้น (Database Schema Overview)
ความสัมพันธ์ของข้อมูลจะถูกเชื่อมต่อกันผ่านตารางหลักๆ ดังนี้:
* `employees` ➡️ จัดเก็บสิทธิ์และรหัส PIN 6 หลัก
* `tables` ➡️ จัดเก็บผังโต๊ะและสถานะความว่าง
* `qr_sessions` ➡️ ควบคุมเซสชันสั่งอาหารแบบไดนามิกของลูกค้า
* `menu_items` ➡️ จัดเก็บข้อมูลราคาและสต็อกสินค้าของร้าน
* `orders` & `order_items` ➡️ ข้อมูลออเดอร์ประวัติการสั่งอาหาร
* `void_logs` ➡️ บันทึกการยกเลิกรายการอาหารโดยละเอียด
* `payments` ➡️ ข้อมูลธุรกรรมบิลแต่ละใบ
